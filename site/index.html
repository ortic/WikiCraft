The wiki your team writes together

WikiCraft is a self-hosted team wiki with a real-time editor, fast search and fine-grained permissions. It's one Rust binary plus PostgreSQL, and runs on a laptop, a VM or Kubernetes.

Why WikiCraft

Everything a team wiki needs, on your own servers

Built for teams that want their documentation in-house, without giving up a modern editor or the features they rely on every day.

Live co-editing

Everyone types in the same page at once and sees each other's cursors. No locks, no lost changes, no "someone else is editing".

Bring your content

Import complete wiki exports with history, attachments, comments and permissions, or Markdown, Obsidian, Notion, HTML and Word. Links into the old wiki keep working.

Yours to run

One binary with the web app inside. Start on a single server, scale out to several replicas when you need to. Backups, metrics and health checks included.

Ready for AI

A built-in MCP server and a retrieval API let assistants search, cite and write pages, always with the permissions of the person asking.

Features

A closer look

Screenshots from a fresh installation. Click any of them to see it full size.

Collaboration

Write together, live

Open a page and start typing. Colleagues in the same page show up with their name and cursor, and their changes appear as they type.

  • Real-time co-editing on a CRDT, so simultaneous changes merge without conflicts
  • Private drafts until you publish, scheduled publishing and minor changes that don't notify watchers
  • Templates and blueprints with variables, and a default template per space or page tree
  • Paste anything: Markdown turns into formatting, spreadsheet cells into tables, images upload on paste or drop
Editor

Every block you need, one slash away

Type / to insert anything, from headings and tables to diagrams, live reports and embeds. Formatting stays at hand in a fixed toolbar.

  • Tables with merged cells, colours, sorting and sticky headers; tasks with assignees, due dates and reminders
  • Callouts, expand blocks, columns, text colours and highlights, code with syntax highlighting, math
  • Diagrams: draw.io and Excalidraw drawings stored in the page, Mermaid, image annotation
  • Embeds (YouTube, Vimeo, Loom, Figma, Miro, Google Docs), link previews, includes and excerpts, links to any block
Comments

Discuss right where the text is

Select a sentence and comment on it, or start a thread under the page. Mention people to pull them in; resolve the thread when it's settled.

  • Inline and page comments with replies, images, likes, resolve and reopen
  • @mentions and watches on pages, page trees or whole spaces
  • Notifications in the app and as e-mail digests, plus a personal "My tasks" list
Structure

Reports that keep themselves up to date

Give pages typed properties like owner, tier or review date. A properties report collects them into a table that updates whenever a page changes.

  • Page properties: text, number, date, person, select, link and page fields
  • Live reports: pages by label, recently updated, open tasks, decisions
  • Spaces with page trees, folders, a blog with Atom feeds, labels, archive and trash
Planning

Plans that live next to the docs

Timelines, live issue tables and decisions sit in the same page as the reasoning behind them. Shown here in the dark theme.

  • Roadmaps brought over from your old wiki become timelines with lanes, bars and milestones
  • Issue chips from Jira, GitHub and GitLab, and live tables from Jira queries
  • Status labels, dates and decisions inline in the text, with reports across spaces
History

Every change, accounted for

WikiCraft keeps every version. Compare any two word by word, inline or side by side, and restore an older one in a click.

  • Version history with word-level comparison and restore
  • "Changed since your last visit" highlights on pages you come back to
  • Audit log for admins, and who viewed a page
Search

Find it in seconds

Full-text search with snippets covers pages, blog posts and the text inside attached files. It forgives typos and understands word forms in your language.

  • Inside attachments: PDF, Office documents and text files
  • Filters and saved searches, plus browser search integration
  • A query language for precise lists: space = ENG and label = runbook and lastModified > now("-30d")
Everywhere

On every screen, for everyone

The same app works on phones and tablets. Light, dark and high-contrast themes, and an interface checked against WCAG 2.2 AA.

  • Mobile layout for reading and quick edits on the go
  • English, German and French, with a per-person language and workspace default
  • Your look: workspace name, logo, accent colour per workspace and per space
And much more

The complete toolbox

WikiCraft covers the long tail that teams depend on once the wiki becomes the place where work is written down.

Permissions

  • Workspace roles and space roles per user, group or the space default
  • Granular rights: add or delete pages, blog posts, comments and files; export; archive
  • Page view and edit restrictions, inherited down the tree
  • "Inspect permissions" and access requests
  • Guests, public spaces and share links with expiry and password

Sign-in and security

  • OpenID Connect: Microsoft Entra ID, Google, GitLab, Okta, Keycloak, Authentik and more
  • GitHub, LDAP / Active Directory and SAML 2.0, several at once, with group sync
  • Two-factor authentication (TOTP), optionally required
  • Audit log, expiring read-only or read/write API tokens
  • Virus scanning with ClamAV, strict CSP and HSTS

Moving in and out

  • Full wiki exports (XML and cloud formats) with history, comments, restrictions, authors and 50+ macros, plus a dry-run report
  • Update imports bring later changes across; old URLs redirect to the imported pages
  • Markdown and Obsidian vaults, Notion (databases become page properties), HTML and Word
  • Export pages as PDF (typeset, with cover and contents), Word, Markdown or HTML
  • Whole spaces as a static site, a Markdown tree or a restorable backup

Integrations

  • REST API with an OpenAPI 3.1 description
  • Webhooks, signed with HMAC; ready-made formats for Slack, Mattermost, Microsoft Teams and Google Chat
  • Issue chips and live tables from Jira, GitHub and GitLab
  • Embeds and link previews for the tools your team already uses

AI

  • Built-in MCP server: assistants search, query, read and write pages with the user's permissions
  • Retrieval API for RAG: passages cut along headings, hybrid keyword and semantic ranking, a link to the exact block
  • Semantic ranking with any OpenAI-compatible embeddings API, local models included
  • Optional "Ask the wiki" answers with citations

People and administration

  • Profiles with photos, a people directory, following colleagues' activity
  • Invitations, groups, deactivation, merging imported authors into real accounts
  • Announcement banner, feature switches, attachment limits and blocked file types
  • Usage overview, space directory and categories
Get started

Running in five minutes

All you need is Docker. WikiCraft and PostgreSQL start together; the first visit opens a setup wizard that creates your workspace and admin account.

git clone https://github.com/ortic/WikiCraft.git
cd WikiCraft
export WIKICRAFT_DB_PASSWORD=$(openssl rand -hex 16)
docker compose up -d   # builds the image on first start

Then open http://localhost:8787. The compose file starts PostgreSQL 17 with pgvector and keeps data in two volumes. Without WIKICRAFT_DB_PASSWORD the database password is change-me.

Needs Rust 1.94 or newer, Node 20.19+ or 22.12+ and PostgreSQL 15 or newer. Release builds embed the web app, so the result is a single file you can copy anywhere.

git clone https://github.com/ortic/WikiCraft.git
cd WikiCraft
(cd web && npm ci && npm run build)
cargo build --release -p wikicraft

export WIKICRAFT_DATABASE_URL=postgres://wikicraft:secret@localhost:5432/wikicraft
export WIKICRAFT_BIND=0.0.0.0:8787
./target/release/wikicraft serve   # migrations run on startup

The manifests in deploy/kubernetes run several replicas: attachments in S3-compatible storage, search and live editing shared through PostgreSQL, no sticky sessions. Build the image and push it to your registry first.

docker build -t registry.example.com/wikicraft:latest .
docker push registry.example.com/wikicraft:latest

cd deploy/kubernetes
cp secret.example.yaml secret.yaml
# edit secret.yaml, configmap.yaml, ingress.yaml and the
# image in kustomization.yaml, then:
kubectl apply -k .

After the first start

  1. Put it behind HTTPSSet WIKICRAFT_BASE_URL to your address and WIKICRAFT_SECURE_COOKIES=true.
  2. Connect sign-inAdd OIDC, GitHub, LDAP or SAML providers in WIKICRAFT_AUTH_PROVIDERS.
  3. Turn on e-mailWIKICRAFT_SMTP_URL enables notifications, digests and password resets.
  4. Bring your contentAdmin → Import takes wiki exports, Markdown, Notion, HTML and Word files.
  5. Schedule backupswikicraft backup wikicraft.zip saves the database and files in one archive.
Deployment

Small team or whole company

WikiCraft is a stateless binary. Run one instance with local storage, or several behind a load balancer. The same build does both.

Single instanceScaled (several replicas)
Start withdocker compose up -ddeploy/kubernetes or the scaled compose file
DatabasePostgreSQLPostgreSQL (managed or HA recommended)
AttachmentsLocal volumeS3-compatible storage (S3, MinIO, R2, Ceph)
SearchEmbedded indexShared index in PostgreSQL
Live editingIn-processReplicas relay edits through PostgreSQL, no sticky sessions
Background jobsPostgreSQL queue; any replica picks up work, crashed jobs are detected
Observable

Prometheus metrics, JSON logs with request ids, liveness and readiness probes.

Safe upgrades

Migrations run on startup under a lock, so rolling updates with several pods just work.

Backups

One command for database and files; restore into an empty database to move servers.

Hardened

The container runs as non-root and works with a read-only root file system. Strict CSP and HSTS.

For developers

Built to be built on

Everything in the interface is in the API. Personal tokens can be read-only, and every call goes through the same permission checks as the app.

REST API

Versioned under /api/v1, described in OpenAPI 3.1 at /api/openapi.yaml. Write pages as ProseMirror JSON or plain Markdown.

curl -X PUT https://wiki.example.com/api/v1/pages/$ID/content \
  -H "Authorization: Bearer wct_…" \
  -H "Content-Type: application/json" \
  -d '{"markdown": "# Release notes\n\nShipped today."}'

AI assistants (MCP)

Point any MCP client at your wiki. Assistants search, query, read and write pages with the token owner's permissions.

claude mcp add --transport http wikicraft \
  https://wiki.example.com/api/mcp \
  --header "Authorization: Bearer wct_…"

Retrieval for RAG

Ask a question, get the passages that answer it, each linked to the exact block, filtered by what the caller may read.

curl -H "Authorization: Bearer wct_…" \
  "https://wiki.example.com/api/retrieve?q=rotate+VPN+certificates&limit=5"
